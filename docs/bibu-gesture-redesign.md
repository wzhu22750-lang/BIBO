# BIBU 长按滑动优化方案

## 目标与边界

把“弹出一排机械按钮”改成“从 BIBU 心心里展开的情绪小扇面”：像素外观不变，运动柔和、选择跟手、取消可靠。保留轻点即发和六种既有情绪，不改发送协议。

本文件是实施规格，不代表功能已经完成。当前工作区已有大量未提交改动，实施者必须保留，禁止 reset、checkout 覆盖、全局格式化、自动提交/推送。原生层、推送链路、环境配置不在范围内。capacitor.config.json 的 server.url 必须保持 https://www.515171.xyz；前端发布后 APK 热更新，无需打包。

## 当前问题（代码审查结论）

- src/components/BottomNav.tsx 用六个文字 pill 和极小英文说明，像操作面板，缺少情绪辨识度。
- src/expectations.css 使用 wrap 排列，长短标签改变空间分布；六种情绪缺少独立图形。
- 每次 pointermove 读取全部选项的动态 bounding rect，动画影响命中；重叠扩展热区最后一项覆盖前项。
- 滑出所有选项不清空 hoveredKind，松手可能误发上一个选项；拖到当前默认情绪不算 draggedToPill，行为不一致。
- 长按后无限 heartbeat 与 :active/:hover 都在控制 transform，反馈互相抢夺；缺少完整收起过程。
- 默认短按和长按共享若干 boolean，取消、失焦和多指情况下易残留状态。

## 视觉：情绪小扇面

1. 保留底部中央像素心心，扩大隐形触摸目标到至少 44 × 44 CSS px，不挤压相邻导航。
2. 长按时六个像素图形从按钮附近向上展开，形成浅弧形反应条。不是巨大的圆盘菜单，也不是六张卡片。固定顺序：哔卟哔卟、想你、抱一下、快来、晚安、我回来啦。
3. 复用 lovePings.art 对应的 PixelArt 图形：心、兔、熊、飞机、月亮、狗。所有装饰与图标使用已有 SVG 组件或像素 SVG；禁用 emoji、位图、毛玻璃、模糊光晕。
4. 使用项目的 paper / ink / yellow / pink 等 tokens。淡底承托、克制硬边阴影，移除旧大方框和 pill 边框堆叠。以大图形为主、每项短中文标签为辅，当前项上方显示清楚的情绪名。
5. 选中项轻抬 8–12px、放大至约 1.15，其余保持可辨认；只给当前项黄色或粉色底，不做六色彩虹。
6. 以视口约束布局，而不是仅相对按钮居中。320px 宽仍容纳六个至少 44px 的固定命中槽，左右安全边距至少 8px；字大模式不裁字，必要时增加高度。手机横屏和安全区同样检查。
7. 提示只留一句：初始“滑向一个心情”；命中“松开发送「想你」”；离开“松手取消”；长按未滑动松开后“点一个心情发送”。不使用 tiny 英文口号。

## 手势契约

| 输入 | 必须发生的行为 |
| --- | --- |
| 短按 | 沿用 bibu.send()，只发送一次 |
| 按下约 300ms | 展开选择器，轻触觉反馈一次，不发送 |
| 阈值前明显移动超过约 12px | 取消本次点击与长按，避免无意发送 |
| 展开后滑入选项 | 更新当前候选，包括原先默认项；仅跨项时轻震一次 |
| 在选项有效热区松开 | 用松手坐标重新判定，bibu.send(kind) 恰好一次 |
| 滑出有效范围/滑回中心 | 清空候选，明确取消预览；松手取消且不发送旧选项 |
| 长按但从未尝试选择，原地松手 | 保留选择器，允许点选；不自动发送 |
| 保留模式点选 | 发送对应情绪一次后关闭 |
| Escape、点外部、路由变化、失焦、pointercancel、异常 lostpointercapture | 取消并清理，不发送、不留下幽灵点击 |
| 非主按钮/第二根手指 | 不开始新手势、不覆盖主指针 |
| disabled/busy | 不接受新发送；手势中变 disabled 时取消 |

正常 pointerup 释放 capture 导致的 lostpointercapture 不能误伤保留模式。捕获不可用时使用受控 window pointermove/up/cancel 回退，并完整清理。抑制长按后合成 click，但不得吞掉后续键盘点击。

## 跟手与动效

- 按下立即轻微压缩（约 0.94）；不是等待 300ms 后才反馈。
- 展开约 220–300ms：整体从下向上，选项间隔约 18–25ms，轻弹一次即停。
- 使用已安装的 framer-motion，AnimatePresence 处理退出，spring 初值 stiffness 420 / damping 30 / mass 0.7，可实测微调。不要为此添加 motion 或其他依赖。
- 手指附近图形可有不超过 4px 的跟随偏移，连续坐标用 motion values，不通过 React state 每帧重渲染。
- 固定布局命中槽与动画图形分离。展开时测量稳定容器；resize 重新测量；按最近槽位判定且边界有约 6–8px 滞回，避免两个选项之间抖动。超过整体取消边界必须立刻清空，不得用滞回来保留旧选择。
- 收起约 140–180ms，向按钮回收；发送时给一次短促离手反馈。不要把本地动画称为网络发送成功；成功/失败继续沿用现有 useBibu toast，不修改其 API。
- 只动画 transform/opacity，移除无限 heartbeat 与 transform 冲突。prefers-reduced-motion 下关闭弹簧、跟随和错峰，保留即时状态变化。

## 工程拆分

- BottomNav.tsx 只保留导航组装，把 BIBU 控件拆成独立 BibuSendControl.tsx（或同等明确命名）。保留已有导航逻辑及其他未提交改动。
- 手势状态明确区分 idle / pressing / dragging / pinned；指针 id、计时器、最后坐标保存在 refs，离散状态使用 reducer 或清晰状态机。
- 把候选命中与手势决策提取为可测试纯逻辑，避免依赖动画后的 DOM rect。
- 样式采用独立作用域文件，删除旧选择器专属冲突样式，检查 src/fontscale.css 的旧规则。不要改全局设计 tokens。
- 继续消费 lovePings 和 BibuAction；不要复制消息内容、改 LovePingKind 或业务发送实现。
- 选择器提供真实 button、中文 aria-label、aria-expanded/controls、可见焦点；方向键或明确键盘入口打开，方向键切换、Enter 发送、Escape 关闭并回焦 BIBU。无障碍播报只随离散候选变化，不逐帧播报。与“更多”互斥。

## 验收与交付

1. 先记录现有 git status 和构建/测试基线，后续故障区分已有失败和新引入失败。
2. 测试至少覆盖：短按一次、六种拖发含默认项、跨项切换、拖出取消、中心取消、原地长按保留并点选、阈值前移出、连续操作、禁用切换、多指、pointercancel、失焦、捕获失败、正常释放后的 lostpointercapture、键盘操作。
3. 执行 npm run typecheck、npm test、npm run build；仅对修改文件运行 prettier 检查。
4. 浏览器在本地 demo 或 mock 模式验证，不向真实伴侣发测试通知。检查 320/375/390/430px、横屏、大字体、reduced motion；截图包含收起、展开、命中、取消四态。不要只用静态截图宣称手势跟手。
5. 检查所有新图标 DOM 有 SVG、无横向滚动、菜单不被导航裁切，候选不被手指完全遮挡。
6. 交付修改文件清单、测试命令与真实结果、截图路径、未验证项。没有 Android 真机测试就明确写出，不宣称真机体验通过。禁止自动部署。
